# Agent working rules

## Stack

pnpm + TypeScript + React + Vite + Tailwind v4 + shadcn/ui, with a
Cloudflare Worker backend ("Workers with static assets" via
@cloudflare/vite-plugin, config in wrangler.jsonc) and PocketBase as the
database. Tested with Vitest (unit: `src/`, `worker/`, `shared/`) and
Playwright (e2e: `e2e/`), linted with ESLint, formatted with Prettier.

- TypeScript runs side-by-side per the official TS 7 guidance: `tsc` (and
  `pnpm typecheck`) is the native TS 7 compiler via the `@typescript/native`
  alias, while the `typescript` package is aliased to
  `@typescript/typescript6` because typescript-eslint requires the TS 6 API.
  Do not "simplify" this to a single `typescript` dependency.
- TS 7 removed `baseUrl`; keep `paths` entries relative to the repo root.
- Three TypeScript projects: `tsconfig.app.json` (src + shared, DOM lib),
  `tsconfig.worker.json` (worker + shared, Workers runtime types from the
  generated `worker-configuration.d.ts`), `tsconfig.node.json` (configs,
  e2e, scripts + shared).
- `shared/` must stay runtime-agnostic (no DOM, no Workers globals, no
  React, no Node modules): the browser, the Worker and the Node scripts all
  import it. Node runs the scripts by stripping types, so inside `shared/`
  and `scripts/` relative imports need the `.ts` extension and only
  erasable syntax is allowed (no enums or parameter properties;
  `erasableSyntaxOnly` enforces it).
- `worker-configuration.d.ts` is generated by `wrangler types` (gitignored);
  `pnpm typecheck` regenerates it. The Worker's bindings are declared by
  hand in `worker/env.ts` because they are secrets, unknown to
  `wrangler types` without `.dev.vars`.
- Vitest runs with globals off; always import `describe`/`it`/`expect` from
  `vitest`. Worker and shared tests start with `// @vitest-environment node`.
- `vitest.setup.ts` registers Testing Library `cleanup()` explicitly; do not
  remove it, or rendered components leak across tests.
- Add shadcn/ui components with `pnpm dlx shadcn@latest add <component>`.

## Workflow

After making changes from a prompt and BEFORE committing:

1. Author new tests covering the changes being made.
2. Update any documentation affected by the changes (README, this file).
3. Run `pnpm format-and-validate` and repair any regressions in-line. This
   includes the Playwright e2e suite; never skip it.

Commit in small, modular units (one logical change per commit).

## Product invariants

- **No email is ever stored, logged or returned.** OAuth completes in the
  Worker (`worker/auth.ts`); the email goes straight into
  `emailHash(email, EMAIL_PEPPER)` (`shared/hash.ts`) and only the hash is
  kept. The hash never leaves the Worker either: the public id of a person
  is their record id. The OAuth picture lives in the sealed session cookie
  and is stored only if the person picks it as their avatar.
- **The Worker is the only database client.** Every collection rule is null
  (superuser only) and the browser talks only to `/api`. All access goes
  through the `Datastore` interface (`shared/db.ts`); don't call PocketBase
  from anywhere but `shared/pocketbase-db.ts`. Timestamps are plain date
  fields written by the caller, never autodate.
- **A submitted ticket is immutable.** `worker/tickets.ts` rejects every
  write once `status` is `submitted`. The only exception is
  `mergeVenues` (`shared/merge.ts`), which swaps an outgoing venue id for
  the surviving one on tickets and venue nodes and bumps those nodes'
  `updated`.
- **Submit order:** venue (created if new), then the ticket record, then
  nodes and edges (`shared/submit.ts`). People nodes and venue nodes are
  reused; each ticket adds one edge per attendee to the venue and one per
  pair of attendees. The seed goes through the same function.
- **Privacy of tickets:** an open ticket is readable by anyone holding its
  code (the code is the invitation); a submitted one only by its creator
  and participants. The public graph (`/api/graph`) exposes ids, avatars,
  venue names and locations, and edges, and nothing else.
- **The QR link is `<origin>/?ticket=<code>`** so any camera app can open
  it; `src/App.tsx` forwards it to `/ticket/<code>`, and the sign-in and
  onboarding detour returns there (`next`, validated by `safeNext`).
- **Every venue has a lat/lng.** A ticket can't be created without one.
- **State-changing requests require the app's `Origin`** (`worker/index.ts`).
- **`DEV_LOGIN=1` is for local development and e2e only.** It lets anyone
  sign in as anyone. Never set it in production.
- **Light and dark themes.** The theme is the `dark` class on `<html>`;
  `index.css` defines light tokens on `:root` and dark ones on `.dark`, so
  every colour must come from a token. The graph/globe stage (`--stage`) is
  dark in both themes, and the ticket (`--ticket`) is paper-coloured in both
  so the QR code always has contrast. An inline script in `index.html`
  applies the theme before first paint and mirrors `src/lib/theme.ts` (key
  `irl:theme`, theme-color values): change both together.
- Mobile-friendly: page padding is the `safe-x` utility; the e2e specs guard
  against horizontal scroll.

## Gotchas

- `assets.run_worker_first` is `true` and `not_found_handling` is
  `single-page-application`, so deep links serve `index.html`; the Worker
  only handles `/api/*`.
- E2e runs the real stack (`playwright.config.ts`): a second PocketBase on
  port 8191 with `pocketbase/pb_data_e2e` (wiped each run, seeded by
  `e2e/global-setup.ts`) and the app on 5198 with `CLOUDFLARE_ENV=e2e`,
  which makes the Worker read the committed `.dev.vars.e2e`. That file sets
  `OSM_LOOKUP=off` so runs never hit the public OpenStreetMap servers.
  Specs create their own people ("Sign in as a new person") so they don't
  disturb each other.
- PocketBase is pinned (`PB_VERSION` in `scripts/pocketbase.sh`) and
  downloaded by `scripts/pocketbase-download.ts`, which reads the zip itself
  because the CI container has no `unzip`.
- **Focus is a node id in the URL** (`?focus=`), so it carries between the
  graph and the globe. `focusGraph` (`src/lib/focus.ts`) keeps the node, its
  direct neighbours and only the links that touch it. `graph-view.tsx` keeps
  node objects in a module-level map so positions survive narrowing and
  widening.
- **Keep every prop passed to the globe and the force graph referentially
  stable** (module constants, `useMemo`, `useCallback`). Both libraries
  rebuild a layer when a prop changes identity, so an inline accessor
  rebuilds that layer on every React render, and on phones the stage
  re-renders whenever the browser toolbar resizes it.
- **The heat overlay is ours, not the globe library's.** The library's
  `heatmapsData` layer evaluates a density estimate for about 200k vertices
  on the main thread, which froze phones for seconds when switching to it.
  `src/lib/heat-texture.ts` draws the heat as an equirectangular canvas
  image instead, and `globe-view.tsx` wraps it on one sphere added to the
  globe's scene. Don't switch back to `heatmapsData`.
- Arcs are grouped by one-degree cell (`arcs` in `src/lib/globe-data.ts`)
  and drawn with reduced tube detail, so switching to them builds tens of
  small meshes rather than hundreds of detailed ones.
- Nothing over the stage uses `backdrop-blur` (re-blurring a canvas that
  redraws every frame is expensive on phones), and the stage is
  `touch-none` so a drag turns the view instead of scrolling the page. On
  touch devices the globe renders without antialiasing at a pixel ratio
  capped at 1.5 (`globe-view.tsx`).
- three-globe's colour parser doesn't accept the space-separated
  `hsl(h s% l%)` form; a colour it can't parse makes the shape invisible.
  Use comma syntax or hex for anything passed to the globe.
- MapLibre parses tiles in a module worker. `src/components/venue-map.tsx`
  imports it with `?worker&url` and `vite.config.ts` sets
  `worker.format: "es"`; without both the map shows no streets.
- The graph, globe, map and scanner pages are lazy so the first load
  doesn't include three.js or MapLibre.
- The OpenStreetMap services want a client name in `User-Agent`
  (`worker/venues.ts`) and are rate-limited; responses are cached at the
  edge for a day, and a failed lookup still returns known venues.
- CI's `validate` job runs in `mcr.microsoft.com/playwright:v<version>-noble`,
  with the version read from `pnpm-lock.yaml`, so bumping `@playwright/test`
  bumps the image.
- `wrangler preview` fails unless `wrangler.jsonc` has a `previews` block;
  keep the empty `"previews": {}`.
